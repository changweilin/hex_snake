# Follow-up Execution List

這份清單整理目前較值得排入後續開發的事項。`doc/current-balance.md` 已刪除，平衡判斷請改以最新 `reports/` 輸出或重新執行模擬結果為準。

## P0

- 修正文字編碼與文案資料
  - 範圍：`README.md`、`data/characters.json`、`doc/` 中的角色與說明文案。
  - 目標：確保繁體中文在瀏覽器、終端、Git diff 與文件中都能穩定顯示。
  - 驗收：角色選單、規則、README、角色文件不出現亂碼。

- 建立新手引導
  - 範圍：首次進入遊戲、角色選擇、移動、食物資源、小招、大招、勝敗條件。
  - 目標：讓新玩家不讀文件也能完成第一場對戰。
  - 驗收：首次啟動會出現簡短教學；玩家可略過，略過偏好會保存到 `localStorage`。

## P1

- 建立最新平衡基線
  - 範圍：重新執行模擬，產生新的角色勝率、對戰矩陣與摘要。
  - 目標：不要再引用舊的 `doc/current-balance.md`，改由最新報告判斷角色強弱。
  - 驗收：`reports/` 有新的輸出檔，並整理一份短摘要供後續調整使用。

- 強化手機操作手感
  - 範圍：虛擬搖桿、攻擊按鈕、攻擊預覽、左手模式、小螢幕 HUD。
  - 目標：降低誤觸，讓移動與放招的意圖更清楚。
  - 驗收：手機寬度下控制區不遮擋棋盤，攻擊預覽與按鈕狀態清楚可辨。

- 製作角色展示 / 圖鑑模式
  - 範圍：角色立繪、人型 / 幻獸 / Q 版切換、技能名稱、偏好食物、音效預覽。
  - 目標：讓既有角色素材能被完整瀏覽，也作為玩家理解角色差異的入口。
  - 驗收：可從遊戲主畫面開啟圖鑑，並瀏覽所有角色與主要素材。

## P2

- 拆分 `index.html`
  - 範圍：將大型單檔逐步拆成遊戲核心、UI、音效、重播、資料載入等模組。
  - 目標：降低後續維護成本，不改變現有遊戲行為。
  - 驗收：拆分後 `npm run test:quick` 通過，瀏覽器可正常啟動與遊玩。

- 建立測試 / 報告儀表板
  - 範圍：讀取 `reports/` 中的 csv/json，顯示角色勝率、對戰矩陣、策略比較。
  - 目標：讓平衡與 AI 調整可以視覺化追蹤。
  - 驗收：本機可開啟 dashboard，選擇報告後看到摘要表格與矩陣。

## Routine Checks

後續每次改動資料、技能、AI 或平衡時，至少執行：

```bash
npm.cmd run test:quick
```

若改動碰撞、攻擊、AI 決策或模擬核心，再執行：

```bash
npm.cmd test
npm.cmd run simulate
```
